# Встроенный MIDI/AdLib-драйвер и его внутренние форматы

## 1. Область доказательства

Документ описывает **исследованный SNAKE.EXE**, а не произвольную реализацию MIDI. Основание — инструкции сегмента `1341`, таблицы в `DGROUP`, три распакованных ресурса `MUS1.MID`–`MUS3.MID` и их полный событийный разбор. Адреса вида `1341:183E` относятся к исходной раскладке EXE до загрузочной релокации. Файловое смещение такой процедуры равно `0x14410 + 0x183E`.

Символические инструкции всего MIDI-блока находятся в [MIDI.ASM](../full/sound/exact/MIDI.ASM), читаемое C-представление — в [MIDISND.C](../full/sound/MIDISND.C) и [MIDISND.H](../full/sound/MIDISND.H). Полное сравнение 4193 байт блока, его PUBLIC-адресов и релокаций записано в [module_midi.json](../full/sound/exact/module_midi.json). Это доказывает точность ассемблерного представления; оно **не означает**, что все C-функции этого блока уже дают те же инструкции при компиляции. Происхождение и статус двух представлений разделены в [PROVENANCE.md](../full/sound/exact/PROVENANCE.md).

## 2. Файловый контейнер и реально использованные события

Внешняя структура — Standard MIDI File: `MThd`, шестибайтовый заголовок, затем `MTrk`. Длины чанков и числа заголовка записаны **big-endian**. Все три имеющихся ресурса имеют format 0, один трек и division 480. Их внешнее размещение в GPF описано в [GPF_RESOURCES.md](GPF_RESOURCES.md).

| Ресурс | Размер файла | Событий | Последний tick | Семейство `9n` | SysEx `F0` |
|---|---:|---:|---:|---:|---:|
| `MUS1.MID` | 44146 | 11260 | 226596 | 11232 | 12 |
| `MUS2.MID` | 36433 | 9277 | 226596 | 9260 | 8 |
| `MUS3.MID` | 15857 | 3972 | 153839 | 3958 | 10 |

Это подсчёт записей событий, а не числа одновременно звучащих нот. В `9n` входят также Note On с нулевой velocity, которыми завершаются ноты. Подробные данные, типы SysEx, длины и извлечённые 30-байтовые инструменты находятся в [midi_engine_evidence.json](../analysis/midi_engine_evidence.json). Полный список событий сохранён в `analysis/gpf-metadata/*.MID.json`.

Поиск чанка выполняет `1341:0406`. Он проверяет `MThd`, выбирает индекс трека и проходит длины предыдущих чанков. Прибавление к дальнему указателю использует 16-битное смещение; это не универсальный обработчик треков произвольного размера. Временная шкала секвенсора непосредственно использует **480 ticks на долю**, а не произвольное поле division. Имеющиеся ресурсы этому соответствуют. [Основание: `SOUND.C`, `MIDISND.C`, процедуры `0406`, `0DB9`, `0E7C`.]

## 3. Задержки, темп и позиция

Перед событием стоит MIDI VLQ: семь младших битов каждого байта добавляются к накопителю, старший бит сообщает о продолжении. Процедура `101E` реализует это через `SHL/RCL` и флаг переноса, возвращая 32-битный результат в `DX:AX`. Она не проверяет стандартный предел в четыре байта. При слишком длинном значении арифметика переполняется по фактической разрядности регистров. [Основание: [MR101E.ASM](../full/sound/readers/MR101E.ASM).]

Секвенсор хранит абсолютное время очередного события, текущее время и дробный накопитель. Начальный темп — 500000 микросекунд на четверть; начальная скорость — 128. При установке темпа выполняется целочисленное вычисление:

```c
rate = (tick_period << 10) / (unsigned short)(tempo >> 6);
```

Отдельная процедура `0814` учитывает коэффициент скорости. На каждом шаге старшее слово дробного накопителя переносится в целые ticks, затем очищается. Номер доли хранится с единицы, tick внутри доли — с нуля. Деление и остаток вычисляются по 480. Реконструкция сохраняет исходные целочисленные округления. [Основание: `0DB9`, `0E7C`, `0FBE`, `0814`.]

Обработчик meta `FF 51` читает три байта темпа непосредственно; он пропускает один байт длины и не проверяет, что тот равен 3. `FF 2F` завершает последовательность. Остальные meta пропускаются по VLQ-длине. Неизвестные системные статусы прекращают разбор, обнуляя дальний указатель. Это особенности данного исполняемого файла, которые нужно учитывать при создании совместимых ресурсов. [Основание: `183E:19AA..1A49`.]

## 4. Подмножество MIDI-событий

| Статус | Данные после статуса | Поведение этого драйвера |
|---|---|---|
| `8n` | note, velocity | Завершает ноту; velocity не используется |
| `9n` | note, velocity | Начинает ноту; velocity 0 завершает её |
| `An` | два байта | Пропускает оба байта |
| `Bn` | controller, value | Обрабатывает перечисленные ниже контроллеры |
| `Cn` | program | Выбирает инструмент из внутреннего банка |
| `Dn` | один байт | Пропускает байт |
| `En` | два байта | Пропускает оба байта: ячейка таблицы ведёт в `18EA` |
| `F0` | VLQ-длина, payload | Для производителя `7D` вызывает внутренний SysEx-диспетчер |
| `F7` | VLQ-длина, payload | Пропускает блок по длине |
| `FF` | meta, длина, payload | Конец трека, темп или пропуск неизвестной meta |

В теле драйвера есть код pitch bend по адресу `198C`, но штатная таблица событий `1870` **не направляет `En` в него**. Документировать pitch bend как действующую функцию этого файла было бы ошибкой. [Основание: [MR183E.ASM](../full/sound/readers/MR183E.ASM), семь символических элементов таблицы `midi_1870`.]

Running status также реализован ограниченно: байт меньше `80h` трактуется как номер ноты для Note On на последнем запомненном канале `9n`. Драйвер не хранит произвольный предыдущий status. Поэтому корректный по общей спецификации SMF поток с running status для контроллеров или Program Change не обязательно совместим с игрой. Имеющиеся музыкальные ресурсы используют поддерживаемую схему. [Основание: `1849..186B`, `18A0..18A8`, событийные JSON.]

| Controller, десятичный | Назначение | Процедура |
|---:|---|---|
| 1 | Модуляция программных огибающих | `253C` |
| 7 | Громкость партии | `235A` |
| 10 | Вызов функции панорамы; в этом файле она состоит из `RET` | `23D1` |
| 16 | Приоритет партии | `22F1` |
| 17 | Расстройка высоты | `247E` |
| 18 | Дополнительная настройка диапазона высоты | `25E7` |
| 64 | Удержание нот (sustain) | `2567` |

Остальные контроллеры читаются и пропускаются. В `25E7` отдельно сохранена наблюдаемая особенность передачи аргумента: младший байт указателя партии попадает в аргумент канала. Поведение не исправлялось под предполагаемый замысел автора. [Основание: `18F0..197B`, `ADLIB.C`, точные инструкции `ADLIB.ASM`.]

## 5. SysEx производителя `7D`

Событие имеет внешнюю форму:

```text
F0  <VLQ длины L>  7D  <команда>  <параметры>  F7
```

Длина `L` включает байт `7D` и завершающий `F7`. Внутреннему диспетчеру передаётся указатель на команду и длина `L-2`. Некоторые команды после номера команды пропускают ещё один служебный байт. В имеющихся ресурсах такой байт обычно нулевой; код его содержимое не проверяет. [Основание: `19B8..19EB`, `1A4A..1D48`.]

### 5.1. Упаковка полубайтами

В большинстве команд байт параметра передаётся двумя байтами: сначала старшие четыре бита, затем младшие. Для пары `a,b` декодер записывает `(a << 4) | b` с усечением до 8 бит. Проверки диапазона `0..15` нет.

У процедуры `1D49` есть существенная особенность счётчика. Для ненулевого аргумента `count` сначала вычисляется `((count + 2) mod 65536) >> 1`. Если результат ненулевой, он задаёт число читаемых пар. Если результат равен нулю (`count=FFFEh` или `FFFFh`), вход в тело цикла до первой инструкции `LOOP` приводит к **65536 итерациям**. Исходный `count=0` пропускается сразу. Для обычного положительного чётного количества полубайтов процедура читает **одну лишнюю пару**. В корректных имеющихся командах значимые поля помещаются до этого лишнего байта; копирование инструмента забирает ровно 30 байт. Воспроизводящий движок должен сохранять это поведение для точности, а редактор ресурсов должен ограничивать поля по фактической схеме команды. [Основание: [MR1D49.ASM](../full/sound/readers/MR1D49.ASM), `2665`, `2679`.]

### 5.2. Таблица команд

В следующей таблице «декодированные» поля — результат сборки пар полубайтов. 16-битные числа внутри таких блоков записаны big-endian и читаются процедурой `04CC`.

| Команда, hex | Полезные параметры | Действие |
|---|---|---|
| `00` | Сырой канал `&15`, затем 8 декодированных байт | Создать/выделить партию с настройками приоритета, громкости, высоты и инструмента |
| `01` | Сырой канал `&15` | Удалить партии данного канала у проигрывателя |
| `02` | Дополнительные данные не используются | Удалить все партии проигрывателя |
| `10` | Канал, тип `1`, 30 декодированных байт | Назначить инструмент непосредственно партии |
| `11` | Пропускаемый байт, тип `1`, номер, 30 декодированных байт | Загрузить инструмент в глобальную ячейку `0..31` |
| `21` | Канал, тип `1`, декодированные BE16 parameter и BE16 value | Изменить поле инструмента и попытаться обновить голоса |
| `30` | Пропускаемый байт, затем hook, BE16 track, BE16 beat, BE16 tick | Условный переход в другую позицию; подавлен при предварительном сканировании |
| `31` | Пропускаемый байт, затем hook, relative, transpose | Условное изменение транспозиции проигрывателя |
| `32` | Канал, затем hook, enabled | Условное включение/выключение партии |
| `33` | Канал, затем hook, volume | Условная громкость партии |
| `34` | Канал, затем hook, program | Условный выбор инструмента партии |
| `35` | Канал, затем hook, relative, transpose | Условная транспозиция партии |
| `40` | Пропускаемый байт, затем сырые байты-маркеры | Выполнение очереди команд, привязанной к маркеру |
| `50` | Пропускаемый байт, затем пять BE16: count, start beat, start tick, end beat, end tick | Установить цикл секвенсора |
| `51` | Дополнительные данные не используются | Снять цикл |
| `60` | Канал и последовательность полубайтов | Особая ветвь выбора программы; содержит повреждение регистра курсора `SI` |

Для hook=0 действие выполняется без сравнения. Ненулевой hook должен совпасть с сохранённым значением соответствующего hook-поля; при совпадении поле сбрасывается. Все имена полей восстановлены по их использованию, а не извлечены из отладочных символов. [Основание: `109C`, `10E7`, `1118`, `114D`, `1182`, `11B7`.]

Команда `60` не описывается как корректный обычный BE16-декодер: после чтения второго байта код помещает промежуточное число в `SI`, а следующие `LODS` продолжают использовать `ES:SI` как указатель. Точный эффект зависит от содержимого памяти по изменённому адресу. Команда `21` также попадает в наблюдаемый дефект `26C3`: адрес для обновления голосов читается из таблицы полей, а не из исходной партии. Обе последовательности сохранены в точном представлении. [Основание: `1D12..1D42`, `26C3..2708`.]

В трёх поставленных ресурсах реально встречаются только `00`, `02`, `10`, `11` и `30`. Наличие других обработчиков доказывает их реализацию в EXE, но не использование этими мелодиями. Глобальные номера инструментов: `MUS1` — 3, 5, 11, 13, 16; `MUS2` и `MUS3` — 16. [Основание: [midi_engine_evidence.json](../analysis/midi_engine_evidence.json).]

## 6. Внутренний инструмент: 30 байт

Эта запись передаётся в SysEx `10`/`11`. Она отличается от внешних банков `.SND`, описанных в разделе 6 документа о GPF. В памяти есть 32 глобальные записи и по одной 30-байтовой записи на каждую из 32 партий. Процедуры `2665`/`2679` копируют ровно 30 байт; номер программы ≥32 выбирает встроенную запись по умолчанию. [Основание: `2665..26C2`, `SNDATA.C`.]

| Смещение, десятичное | Размер | Содержимое и использование |
|---:|---:|---|
| 0 | 1 | Флаги/множитель модулятора, отправляются в OPL `20h+slot` |
| 1 | 1 | Старшие биты масштабирования и исходный уровень модулятора |
| 2 | 1 | Параметры атаки/спада модулятора; перед записью в `60h+slot` байт инвертируется |
| 3 | 1 | Параметры sustain/release модулятора; перед `80h+slot` байт инвертируется |
| 4 | 1 | Форма волны модулятора в младших битах и коэффициент влияния velocity в старших |
| 5–9 | 5 | Аналогичные параметры несущего оператора |
| 10 | 1 | Соединение операторов и обратная связь, регистр `C0h+channel` |
| 11 | 1 | Флаги первой программной огибающей |
| 12–19 | 8 | Данные первой программной огибающей |
| 20 | 1 | Флаги второй программной огибающей |
| 21–28 | 8 | Данные второй программной огибающей |
| 29 | 1 | Ограничение длительности голоса; 0 отключает, иначе первоначальное значение умножается на 63 |

Значения уровней преобразуются с учётом velocity и громкости партии через таблицу `snd_volume_products[64][32]`. В аддитивном режиме громкость влияет на оба оператора; иначе отдельная коррекция модулятора отличается. Точные преобразования находятся в `278D` и `2E9B`, поэтому байты инструмента нельзя без преобразования считать готовым снимком регистров OPL. [Основание: `ADLIB.C`, `ADIO.ASM`.]

Флаги огибающей: бит 7 включает её; бит 6 включает управление глубиной через modulation; бит 5 задаёт повтор; бит 4 — повторное включение голоса при соответствующем переходе; младшие четыре бита выбирают параметр через 16-байтовую таблицу `snd_parameter_map`. Восьмибайтовый блок содержит timeout, время и уровень первой стадии, время и уровень второй, время третьей, время и уровень четвёртой. Уровень третьей стадии фиксируется в ноль. Старшие биты некоторых значений включают рандомизацию; расчёт шагов, остатков и масштабирования задан процедурами `2C59`, `2D33`, `2DD3`, `2E7A`. [Основание: `29A1`, `2BF6`, `SNDATA.C`.]

Таблица `snd_instrument_fields` содержит 69 записей по 4 байта: `byte_offset:u8`, `shift:u8`, `mask:u16 little-endian`. Это описание отдельных полей 30-байтового инструмента. Сама таблица находится в `DS:0FBE..10D1`; полный набор восстановлен типизированными инициализаторами в `SNDATA.C`.

## 7. Форматы состояния в памяти

Все приведённые далее указатели — **near, 16-битное смещение в DGROUP**, если явно не указано иное. Поля слов и двойных слов в памяти little-endian. Упаковка — побайтная. Эти структуры не являются самостоятельными файлами на диске. [Основание: `MIDISND.H`, `ADLIB.H`, `data_bindings.json`.]

| Объект | Количество × размер | Смещение DS | Назначение |
|---|---:|---|---|
| Проигрыватель | 2 × 18 | `42DA` | Ссылки на секвенсор, hooks и партии; идентификатор звука и параметры |
| Секвенсор | 2 × 52 | `42FE` | Трек, позиция, часы, темп, скорость и цикл |
| Hooks | 2 × 66 | `4366` | Два общих hook и четыре массива по 16 каналов |
| Удержанная нота | 24 × 20 | `43EA` | Ноты, продолжающиеся через переход в другую позицию |
| Изменение громкости | 2 × 16 | `45D4` | Целочисленный шаг, остаток, длительность и ссылка на проигрыватель |
| Элемент очереди | 64 × 16 | `45F6` | Восемь 16-битных слов: тип записи и семь параметров |
| Партия AdLib | 32 × 32 | `4A00` | Канал, инструмент, список голосов и текущие параметры |
| Инструмент партии | 32 × 30 | `4E00` | Рабочие 30-байтовые записи |
| Глобальный инструмент | 32 × 30 | `51C0` | Банк, заполняемый SysEx |
| Голос OPL | 9 × 98 | `5580` | Аппаратный канал и две программные огибающие |

### Секвенсор, 52 байта

| Смещение, hex | Тип | Поле |
|---|---|---|
| `00` | near pointer | Владелец-проигрыватель |
| `02` | u8 | Активность |
| `03` | u8 | Резерв/смежное состояние; общий MIDI running status здесь не хранится |
| `04` | u16 | Идентификатор ресурса |
| `06` | u32 | Смещение текущего события относительно начала трека |
| `0A` | u16 | Индекс трека |
| `0C`, `0E` | u16, u16 | Доля и tick внутри доли |
| `10`, `14` | u32, u32 | Текущее время и время следующего события |
| `18` | u32 | Дробный накопитель |
| `1C`, `20` | u32, u32 | Темп и рассчитанная скорость часов |
| `24`, `25` | u8, u8 | Коэффициент скорости и резервный байт |
| `26` | u32 | Приращение дробного времени |
| `2A` | u16 | Оставшиеся повторения |
| `2C`, `2E` | u16, u16 | Начальная доля/tick цикла |
| `30`, `32` | u16, u16 | Конечная доля/tick цикла |

Установка цикла в `0B2E` принимается только при `unsigned16(start_beat + 1) < end_beat`; затем нулевая начальная доля заменяется на 1. Значение count=0 выключает цикл. Во время воспроизведения цикл проверяется выражением `beat >= end_beat && tick >= end_tick`. Это две отдельные проверки, не лексикографическое сравнение пары. При переходе `12D8` предварительно просматривает выключения звучащих нот, переносит их во временный список и убирает из него ноты, повторно включённые в новом фрагменте. Для этого используются 24 записи удержания, таблица `128 × u16` каналов нот по `DS:415A` и два варианта разбора событий. [Основание: `0B2E`, `0E7C`, `12D8`, `1537`, `183E`, `1263`.]

### Hooks и очередь

В 66-байтовой записи hooks байты 0 и 1 относятся к переходу и транспозиции проигрывателя; диапазоны `02..11`, `12..21`, `22..31`, `32..41` — enable, volume, program и transpose для 16 каналов. Нулевые значения означают отсутствие ожидаемого ненулевого hook. При массовой установке для канала 16 в `0B7E` обнаружено исходное повреждение регистра: восемь слов заполняются значением `DS`, а не повторённым байтом аргумента. Это сохранено и отдельно описано в [ASM_INTERVENTIONS.md](../full/sound/ASM_INTERVENTIONS.md).

Очередь содержит записи типа 0 (ожидание sound/marker) и типа 1 (команда с параметрами). Индексы чтения и записи циклически обходят 64 ячейки. `171D` сверяет текущий звук и маркер, затем выполняет следующие записи типа 1 через дальний диспетчер `00FE`. Процедура `17FC` возвращает 2, если звук ещё ожидает запуска в очереди; это отличает ожидающее состояние от уже играющего. [Основание: `0CC3`, `0D1F`, `171D`, `17BB`, `17FC`.]

## 8. Что проверять при создании совместимого ресурса

Для совместимости с данным EXE нужны format 0/доступный выбранный трек, шкала 480, поддерживаемые статусы, корректные длины чанков и VLQ, существующие определения используемых программ и пары полубайтов для внутренних SysEx. Перенос в стандартный MIDI-проигрыватель может сохранить ноты, но потерять внутренние инструменты, hooks и переходы `7D`.

Полный байтовый разбор ресурсов доказывает их структуру. Проверка точной сборки доказывает соответствие инструкций оригиналу. Эти проверки не заменяют прослушивание всех путей воспроизведения и не устанавливают авторский замысел необычных или повреждённых ветвей. Восстановление сохраняет наблюдаемое поведение, а исправленную версию движка следует выпускать отдельно от эталонной реконструкции.
