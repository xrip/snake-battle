# Проверка генерации кода исходным семейством компилятора

`AIMATCH.C` содержит четыре восстановленные C-функции игрового ИИ, всего950байт исходного машинного кода. Их **реально скомпилировал Borland C++3.1 для16-битного DOS**, затем TurboLink5.1 создал `AIMATCH.EXE`. В исходнике нет inline assembler, массивов машинного кода или включения оригинального EXE.

`MAIN.C` — минимальный вход для отдельной проверки компилятора; полученный EXE не является всей игрой. `AIMATCH.OBJ`, `MAIN.OBJ`, `AIMATCH.MAP` и `COMPILE.LOG` сохранены как воспроизводимое свидетельство сборки. Поставляемые исходные функции также находятся в основном `src/logic.c`.

## Результат

| Функция | Исходный адрес | Размер | Сравнение |
|---|---|---:|---|
| `sb_compare_matches` | `0729:1002` | 86байт | **Все86исходных байт совпадают без изменений** |
| `sb_mirror_x` | `0729:000D` | 167байт | Все инструкции совпадают;3различающихся байта находятся внутри2адресов внешнихCRT-вызовов |
| `sb_rotate_clockwise` | `0729:00B4` | 167байт | То же |
| `sb_match_card` | `0729:1058` | 530байт | Все инструкции совпадают;13различающихся байт находятся внутри3адресовCRT-вызовов и5адресов статических данных |

Для двух преобразований отличаются адреса `F_SCOPY@` и `memcpy`: маленькая проверочная программа размещает CRT в других позициях, чем игра. У сопоставителя отличаются три адреса `F_SCOPY@`, ссылки на три массива инициализации и два слова нулевого результата. Проверяющий скрипт сначала проверяет фактические адреса функций поMAP и байты всех упомянутых констант в обоихEXE, затем **только в памяти сравнения** подставляет исходные адреса. После этой явно описанной привязки совпадают167из167байт каждого преобразования и530из530байт сопоставителя. Сами EXE/OBJ при проверке не изменяются. Все позиции, значения до/после и сырые различия перечислены в `../analysis/logic_codegen_verification.json`.

Такая привязка не равнозначна совпадению полного EXE. Она показывает, что C-компилятор выдал идентичные инструкции конкретных функций с правильными внешними символами; восстановление полной компоновки игры — отдельная задача.

## Сборка

В DOS предоставьте Borland C++3.1 на дискеD в каталоге `BORLANDC`, а этот каталог смонтируйте какC. `BUILD.BAT` выполняет:

```bat
bcc -ml -a- -k -O -r- -Z -G- -M -Id:\borlandc\include -Ld:\borlandc\lib -eAIMATCH.EXE MAIN.C AIMATCH.C
```

Существенны большая модель памяти (`-ml`), байтовое выравнивание (`-a-`), сохранение стандартного кадра стека (`-k`), отключение автоматических регистровых переменных (`-r-`), подавление повторных загрузок регистров (`-Z`) и базовая оптимизация переходов (`-O`). Наборы `-O1`/`-O2` меняют форму циклов и для этих функций не подходят.

В системе с Python выполните из корня пакета:

```sh
python tools/verify_bc_codegen.py path/to/SNAKE.EXE matching/AIMATCH.EXE matching/AIMATCH.MAP --output analysis/logic_codegen_verification.json
```

SHA-256 исходной86-байтной функции сравнения и результата компиляции одинаков:

```
2f5beb3259668a1b42ae945d7d151df4ffd314734810c4bd5a393e8f8c3a2d46
```

Совпадение не доказывает буквальное восстановление авторского текста: при проверке несколько разных, но эквивалентных конструкций `if/else` сгенерировали те же86байт. Это конкретный пример неоднозначности обратного перевода машинного кода в текст C.
