# Аудит полной диагностической сборки

**Это ещё не byte-exact EXE.** Проверка сравнивает действительно собранный TLINK файл с оригиналом; она не меняет ни один исполняемый файл.

Оригинал: 102326 байт, SHA-256 `c4e064a1cf15e438017d4d6443817424f816ce4b749fcc279f2d97dc7bd86821`.  
Сборка: 102726 байт, SHA-256 `2a4553dfd74c701ae2116f012a224d01569a373886a20fb17051454e9dc5e830`.

## Остаток различий

Код SOUND занимает 13559 байт вместо 13157. После него линкер добавил 13 байт выравнивания вместо исходных 15. Поэтому DGROUP переместилась с `1679:0000` на `1692:0000` на 400 байт; размер и все внутренние смещения DATA/BSS/STACK сохранены.

Вне области SOUND вместе с её завершающим выравниванием сопоставлены все 85058 байт загружаемого образа: 85023 совпадают непосредственно. Необъяснённых отличий: 0. Остальные отличия проверены по конкретным MZ/OMF fixup и реально полученным адресам из MAP:

- DGROUP segment relocation: 8 отличающихся байт.
- SOUND far code pointer: 12 отличающихся байт.
- SOUND near dispatch pointer: 15 отличающихся байт.

Это сопоставление адресов служит только доказательством причины отличий. Оно не превращает несовпадающий файл в точную сборку и не применяется к его байтам.

## Воспроизведение проверки

```sh
python full/build/audit_layout.py full/build/diagnostic/SNAKE.EXE --map full/build/diagnostic/SNAKE.MAP --output full/build/diagnostic
```

JSON сохраняет все границы, реальные вкладки MAP, каждое адресное правило и каждое необъяснённое отличие. Конечное условие задачи остаётся полным равенством файла, включая SOUND и MZ.
