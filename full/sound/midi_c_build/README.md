# Ограниченная проверка семантики MIDI C

**Результат: 21 процедура, 172 из 172 выбранных сценариев совпали с оригиналом.**
Проверен сохранённый здесь `MIDISND.OBJ`, полученный настоящим Microsoft C 7.0
из восстановленного `MIDISND.C`. Это дифференциальная проверка поведения
отдельных процедур на конкретных входах. Она **не доказывает семантическую
эквивалентность всего модуля** и **не является подтверждением побайтового
совпадения компиляции C**. Точная сборка всего EXE использует отдельную
символическую спецификацию звукового кода; её статус описан в
[`../exact/PROVENANCE.md`](../exact/PROVENANCE.md).

## Сохранённые материалы

- `MIDISND.C`, `MIDISND.H` — точный снимок исходников проверенной компиляции.
- `MIDISND.OBJ`, `MIDISND.COD`, `MIDISND.LOG` — объект, листинг и журнал
  настоящего компилятора.
- `BUILD.BAT`, `compile.json` — команда компиляции, профиль и хеши её входов.
- `verify.py` — переносимый генератор сценариев и запуск сравнения.
- `semantic.json` — результаты каждой процедуры и сценария, сводка, ограничения
  и SHA-256 использованных исходников, объекта, средств проверки и привязок.

Профиль Microsoft C 7.0:

```text
/AM /G2 /Gs /Ox /Zp1 /NTSOUND_TEXT /Fc
```

Компилятор запускался в DOS с предварительным `hdpmi32 -r`. Сохранённый объект
проверяется непосредственно: повторная компиляция для выполнения теста не нужна.

## Повторение проверки

Нужен Python 3 с доступными пакетами `capstone` и `unicorn`; проверка выполнена
с Capstone 5.0.9 и Unicorn 2.1.4. Из корня этого проекта:

```sh
python3 full/sound/midi_c_build/verify.py
```

Можно запускать скрипт по абсолютному пути из другого рабочего каталога.
Его значения по умолчанию разрешаются относительно собственного расположения:
объект — соседний `MIDISND.OBJ`, эталон — `original/SNAKE.EXE`, результат —
соседний `semantic.json`. Параметры `--object`, `--reference`, `--output`
позволяют явно выбрать файлы. Для отдельной группы процедур:

```sh
python3 full/sound/midi_c_build/verify.py --functions 1041,1086,171D
```

Код завершения 0 означает совпадение всех выбранных сценариев, 1 — найденное
расхождение. Проверка сверяет SHA-256 эталона и соответствие снимков C/H
хешам в `compile.json`. Эталонный EXE читается только для сравнения исполнения;
скрипт не создаёт и не исправляет исполняемый файл игры.

## Что именно сравнивается

Общий исполнитель [`../semantic_vm.py`](../semantic_vm.py) загружает образ
оригинальной программы. В одном запуске исполняется оригинальная процедура,
в другом — соответствующая процедура из настоящего OMF-объекта. Её адресные
фиксации разрешаются через сохранённые привязки символов, а прямые вызовы
соседних процедур связываются с их оригинальными входами.

Оба запуска получают одинаковую память и регистры. **Сегмент стека `SS=9000h`
намеренно отличается от сегмента данных `DS=1679h`.** Это существенно для
процедуры `1341:1041`, вычисляющей разность физических адресов двух far-указателей:
ошибка выбора сегмента при обращении к параметрам стека не была бы скрыта
равенством SS и DS. Все шесть выбранных пар указателей дали одинаковые AX:DX.

Для каждого сценария сравниваются:

- всё окно данных DS размером 65 536 байт;
- сохраняемые ABI регистры `SP`, `BP`, `SI`, `DI`, `DS`, `SS`, `CS`;
- возвращаемые значения в соответствии с типом процедуры: AX:DX у `1041`,
  AX у `11F0`, `167E`, `17BB`, `17FC`;
- последовательность вызовов специально перехваченных процедур и значимые
  биты их аргументов;
- журнал операций вывода в порты.

Неиспользуемые после возврата байты рабочей области стека не сравниваются.
Для процедур с типом `void` содержимое регистров результата не считается
обязательным результатом. Одна процедура ограничена 50 000 инструкций.

Вызванные процедуры преимущественно остаются оригинальными. Часть внешних
эффектов заменена одинаковыми заглушками, записывающими аргументы и возвращающими
AX=0. У аргументов типа byte сравнивается младший байт переданного слова:
старший байт не является частью значения и исходный вызываемый код его не
читает. У указателей и аргументов word проверяются все 16 бит. Конкретные
маски перечислены в `semantic.json` и `verify.py`.

В проверке очереди `171D` сохранён **реальный far-диспетчер `00FE`**. Заглушки
стоят только на выбранных конечных действиях паузы, возобновления и изменения
общей громкости. В проверке чтения событий `1D6D` исполняется настоящий
помощник чтения VLQ `101E`.

## Вывод и ограничения

В выбранных сценариях ошибок восстановленного MIDI C не обнаружено. Отдельно
проверен риск неверной адресации параметров far-указателей через DS вместо SS;
он не проявился. Правки размеров полей и byte-аргументы проверены в машинном
коде реального компилятора, а не только в модели типов на современной платформе.

Проверка не перебирает всё пространство входов, все ветви MIDI/SysEx и все
сочетания состояния драйвера. Она не подменяет все вызываемые функции их C-версиями
одновременно, не проверяет аппаратное воспроизведение и не является полным
запуском игры. Значения `complete_module_semantics_proven` и
`compiler_byte_exact_proven` в отчёте поэтому остаются `false`.

Основные исходники и исходники точной сборки при выполнении этой проверки не
изменялись. Этот каталог сохраняет самостоятельный проверяемый снимок C-кандидата
и ограниченный набор подтверждающих наблюдений.
