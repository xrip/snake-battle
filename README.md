# Snake Battle: полная побайтовая пересборка и форматы

**Весь `SNAKE.EXE` пересобран с точным совпадением всех 102326 байт.** Проверены не только функции, но и MZ-заголовок, порядок всех 879 релокаций, весь образ загрузки, данные, библиотечный код и выравнивание. Итоговый файл находится в [full/build/exact/native/SNAKE.EXE](full/build/exact/native/SNAKE.EXE); машинный результат сравнения — [comparison.json](full/build/exact/comparison.json).

```text
Размер:              102326 байт
Различающиеся байты:  0
SHA-256 оригинала и пересборки:
c4e064a1cf15e438017d4d6443817424f816ce4b749fcc279f2d97dc7bd86821
```

**Граница результата:** точная сборка смешанная — восстановленный C основной игры, символический ASM драйверов/низкоуровневых процедур и исходные библиотечные объекты CRT оригинального компилятора. Читаемые C-версии звукового движка также восстановлены и компилируются, но их полное машинное совпадение пока не получено. Поэтому результат нельзя называть полной byte-exact компиляцией *всего кода только из C*. Точное ассемблерное представление звука и C-кандидаты явно разделены; история исходного языка этого драйвера не объявляется установленной. Подробности — [SOUND_REBUILD_STATUS.md](docs/SOUND_REBUILD_STATUS.md).

Работа выполнена по навыку [reverse-engineer-anything из morluto/rea](https://github.com/morluto/rea), с REA/Ghidra, проверкой реальных 16-битных инструкций и запуском оригинальных DOS-компиляторов. Исследована поставка из 26 файлов; на титульном ресурсе указана V 2.3. Имена функций, типов, файлов и комментарии назначены при реконструкции. Совпадение EXE не восстанавливает автоматически авторские имена, форматирование или комментарии.

## 1. Что именно собирается

| Компонент | Представление в точной сборке | Проверенное покрытие |
|---|---|---|
| Основная игра, интерфейс и редактор | C, Borland C++ 3.1 | Полные вклады модулей, включая все локальные переходы и адресные fixup |
| Чтение ресурсов GPF | C, Borland C++ 2.0 | Полный модуль 1495 байт |
| Общие таблицы и состояние | C-определения, Borland 3.1 | Все 4786 байт данных приложения и раскладка 18893 байт BSS |
| Аппаратный ввод, ожидание развёртки | C с восстановленными аппаратными ASM-фрагментами, BCC/TASM | Полные модули, а не только отдельные функции |
| EGA/VGA Sprite Driver | Символический ASM, TASM 3.1; затем исходный алгоритм кодирования | Все 12374 байта вклада, включая заголовок, таблицы и кодировавшееся тело |
| LZSS | Символический ASM, TASM 3.1 | 142 байта декодера и 4096 байт его рабочего словаря |
| MIDI/AdLib-драйвер | Символическая исполнимая спецификация ASM, TASM 3.1 | Все 13157 байт; ещё 15 байт выравнивания создаёт линкер |
| CRT | Реальные C0L.OBJ и 91 библиотечный объект из CL.LIB Borland 3.1 | Оригинальный библиотечный код, данные, BSS и порядок размещения |
| Итоговый EXE | Оригинальный Turbo Link 5.1 | Весь файл равен исходному, без последующих правок |

24 модуля собираются C-компиляторами: 23 с кодом и один модуль данных `SNDATA`. Суммарный вклад их CODE-секций — **46134 байта**; это счётчик секций, включающий аппаратные inline-ASM фрагменты, а не утверждение о доле «чистого C». Полная раскладка задана в [modules.json](full/build/modules.json), отдельные проверки — в `full/build/proof/`. Точный состав звука приведён в [PROVENANCE.md звукового модуля](full/sound/exact/PROVENANCE.md).

Сборка не читает `original/SNAKE.EXE` как источник выходных байтов. Нет `INCBIN` оригинального EXE, массивов машинного кода вместо процедур, заглушек или исправления готового EXE. Адреса связывает настоящий линкер. Дополнительные OMF PUBLIC-имена разрешают восстановленные межмодульные ссылки, не меняя инструкции или таблицы FIXUPP. Кодируемый EGA-блок заново получается из собранного ASM; исходный зашифрованный блок не используется как шаблон. [Основание: `exact_sound.py`, `aliases.py`, `full/ega/pack.py`, итоговые журналы сборки.]

## 3. Как воспроизвести полный EXE

Нужны Python 3.10+, DOSBox и две установки Borland с исходными `BIN`, `INCLUDE`, `LIB`. В работе использованы **Borland C++ 3.1, Borland C++ 2.0, Turbo Assembler 3.1 и Turbo Link 5.1**. Их происхождение, хэши и точные входы описаны в [EXACT_BASELINE.md](full/build/EXACT_BASELINE.md) и [PROVENANCE.md](docs/PROVENANCE.md). Компиляторы в архив не включены.

Из корня распакованного проекта:

```bash
python3 full/build/exact_sound.py \
  --bc31 /absolute/path/to/BORLANDC \
  --bc2 /absolute/path/to/BC2 \
  --dosbox /absolute/path/to/dosbox

python3 full/build/compare.py full/build/exact/native/SNAKE.EXE \
  --reference original/SNAKE.EXE \
  -o full/build/exact/comparison.json
```

Первый шаг собирает исходники и вызывает настоящий линкер. Второй шаг отдельно читает эталон и проверяет готовый файл. Эта последовательность сохраняет разделение сборки и проверки. Для обычной сборки не используйте диагностические ключи пропуска компиляции.

Основные параметры C-модулей Borland 3.1:

```text
-ml -a- -k- -O -r- -Z -G-
```

У `START` и `RETRACE` сохраняется кадр стека (`-k`); аппаратные модули используют внешний TASM (`-B`). GPF собирается Borland 2.0 с `-ml -a- -k- -O- -r- -Z- -G- -K`. Точные параметры каждого модуля хранятся в `modules.json` и журналах. Произвольная общая строка флагов для всех исходников не воспроизводит этот EXE.

Для запуска поместите пересобранный `SNAKE.EXE` рядом с файлами исходной поставки, включая `SNAKE.GPF`, в DOS-среде. Побайтовое совпадение проверено отдельно от интерактивного прохождения игры; оно не представляется результатом полного ручного тестирования всех экранов и мелодий.

Спецификации содержат адреса процедур, смещения, типы, порядок байтов, размеры, алгоритмы и проверенные исключения. Неустановленная семантика отдельных резервных полей отмечена явно; точное сохранение байтов не подменяется предположением об их назначении.

### Практически существенные особенности

**SNK.** Размер файла `107 + 152*N`. Первый байт задаёт начальное состояние накопительного XOR; далее кодируются паспорт и карты. Последний байт дублирует последний кодированный байт — это не CRC. Клетки карты идут сначала по `x`, затем по `y`, по три байта `{group, negate, symbol}`.

**REC.** После XOR-заголовка идёт полубайтовый поток, старший полубайт первым. `E` вводит результаты раунда, `D` завершает воспроизведение. Токены `0..3` получают смысл из состояния игры. Исходный писатель открывает файл без `O_TRUNC`: у `ANTONY.REC`, `JOKER.REC`, `REMBO.REC` сохранены соответственно 592, 590, 900 байт старого хвоста после логического конца.

**GPF.** Заголовок 33 байта, затем 82 записи по 22 байта. Имеются 78 обычных LZSS-потоков и четыре полноэкранных ресурса по четыре потока — всего 94. Полноэкранная запись имеет нулевой несжатый размер в каталоге, но содержит `4 × 28000 = 112000` распакованных байт.

**BLO.** Обычные изображения и полноэкранные ресурсы используют противоположный порядок цветовых плоскостей: `3,2,1,0` и `0,1,2,3`. Это проверено исходными процедурами. Все 58 графических ресурсов экспортированы в PNG.

**MIDI.** Три SMF имеют division 480 и несут собственные SysEx-команды `7D`. В них определяются 30-байтовые AdLib-инструменты и переходы. Реальный обработчик поддерживает ограниченный running status; стандартный pitch bend пропускается таблицей диспетчера. Поэтому общая спецификация MIDI недостаточна для создания полностью совместимой музыки.

**DOS-тексты.** Русские материалы используют CP866 и CRLF. `SNAKE.ADD` в этой поставке является текстом. DOS EOF и зарезервированные байты сохраняются при точной обратной записи.

## 5. Работа с форматами отдельно от игры

Для следующих операций достаточно стандартной библиотеки Python:

```bash
python3 tools/snk_rec.py decode original/TEST.SNK TEST.json
python3 tools/snk_rec.py encode TEST.json TEST.SNK
python3 tools/snk_rec.py decode original/REMBO.REC REMBO.json
python3 tools/snk_rec.py encode REMBO.json REMBO.REC
python3 tools/snk_rec.py verify original --report snk-rec-check.json

python3 tools/gpf.py pack assets/gpf_manifest.json rebuilt.gpf
python3 tools/gpf.py verify original/SNAKE.GPF assets/gpf_manifest.json
```

Отдельные C89-утилиты в `src/` и `tools/` повторяют чтение/запись форматов в настоящем DOS. Они собираются командой:

```bash
python3 tools/build_dos.py \
  --compiler /absolute/path/to/BORLANDC \
  --dosbox /absolute/path/to/dosbox
```

Это создаёт `GPFTEST.EXE`, `GPFBUILD.EXE`, `SNKRTEST.EXE`, `LOGICTST.EXE`. Данная дополнительная сборка не заменяет полный `SNAKE.EXE` из раздела 3. Для повторного экспорта PNG нужен Pillow; для динамического анализа исходных процедур — Unicorn 2.1.4, для листингов — Capstone 5.0.9.

## 7. Что остаётся неизвестным

Полная побайтовая пересборка EXE достигнута. Отдельная незавершённая задача — получить те же обычные звуковые функции непосредственно компиляцией восстановленного C и установить их исторический компилятор/профиль. Предоставленный точный ASM звука не объявляется доказанным исходным авторским ASM и не засчитывается как совпавший C.

REA/Ghidra обнаружил 519 процедур статического образа, включая CRT; сохранены 511 успешных декомпиляций, пять явных ошибок и три незапрошенные записи. Эти числа описывают первоначальный проход анализатора, а не число восстановленных функций или текущий предел покрытия. Файлы `analysis/decompiler_reference/*.c.txt` — справочный псевдокод, не исходники сборки.

Также нельзя установить по одному EXE исходные авторские комментарии, имена переменных и историю ручных изменений. Внутренние форматы содержат отдельные резервные поля с неустановленным назначением; их размеры и байтовое сохранение документированы. Все эти ограничения отделены от уже доказанного полного совпадения исполняемого файла.
